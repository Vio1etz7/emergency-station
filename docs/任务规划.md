# 2026-11-11 · 应急物资站项目任务规划 v1

> 适用：4 人小组 · 四块 BearPi-HM Nano + E53（SC1 路灯 / IS1 人体 / IA1 农业 / ST1 物流）
> 用途：贴在桌面上，每周对照打勾。**不需要每次问 AI 才知道下一步做什么。**

---

## 0. 先用一张图记住这个系统

```
                    ┌──────────────┐
                    │  云端（可选） │  统计、远程查看
                    └──────┬───────┘
                           │ MQTT
                    ┌──────┴───────┐
                    │  主控 · 路灯板 │  SC1：判断 + 点灯 + 报警
                    │   （SC1）     │  开热点、发广播
                    └──┬────┬────┬─┘
            广播/直发   │    │    │
        ┌──────────────┘    │    └──────────────┐
   ┌────┴─────┐      ┌─────┴────┐        ┌─────┴─────┐
   │ 人体板 IS1│      │ 农业板 IA1│        │ 物流板 ST1 │
   │  有人/没人│      │ 温湿度+风扇│        │ 晃动+NFC  │
   └──────────┘      └──────────┘        └───────────┘
```

**三层，记这三句就够：**

1. **感知层**：三块子板各自测一样东西，测到就报。
2. **联动层**：路灯板收消息、做判断、下命令——**断网也照做**。
3. **云端层**：只是把数据存起来给人看，挂了不影响现场。

> 任何时候你迷路了，就问自己：**我现在改的是哪一层？**

## 1. 六个里程碑（每周一个，看得见摸得着）

| 周 | 目标 | 周末必须能演示的东西 |
|---|---|---|
| W1 | 内核补齐 + 硬件体检 + 双板联动 | 一段 15 秒视频：挥手，灯亮 |
| W2 | 四块板同时在线 | 四块板通电，串口各打印自己的数据，互不干扰 |
| W3 | 三条本地联动规则 | 连续演 3 遍不失败：人来灯亮、潮热开风扇、晃动报警 |
| W4 | 断网可用 + 缓存补传 | 关掉云端服务，联动照旧；恢复后数据补上 |
| W5 | NFC 巡检 + 实测数据 | 手机碰一下出记录；一张时延/丢包数据表 |
| W6 | 彩排 + 报告 + 答辩材料 | 三分钟完整演一遍，不卡壳 |

> **中期检查在第几周？** 填在这里：______。如果中期在 W3 之后，W3 就是死线，W1–W2 要压缩。

## 2. 每周任务清单（做完打勾）

### W1 · 打地基
- [ ] 内核四讲跑通：任务、定时器、信号量、互斥锁、消息队列
- [ ] 把 IA1 采集改成「采集 + 处理 + 打印」三任务，用消息队列串起来
- [ ] 硬件体检：四块板 + 四块 E53 逐个上电，贴标签（板1-路灯…），记录好坏
- [ ] 双板联动：路灯板开热点 → 人体板连入 → 发一个字节 → 灯亮
- [ ] 拍 15 秒视频发群

**本周交付：** 视频 + 硬件状态表 + 三任务版代码

### W2 · 让四块板都说话
- [ ] 统一设备号（板1/板2/板3/板4）和固定 IP
- [ ] 三块子板全部连上热点，各自周期性上报一条数据
- [ ] 路灯板能同时收三路消息，串口打印出来不乱
- [ ] 断电重启后能自动重连

**本周交付：** 一张「设备-IP-功能」对照表 + 四板同时在线截图

### W3 · 三条规则
- [ ] R1 有人 → 灯亮（60 秒无人降亮）
- [ ] R2 温湿度超限 → 风扇开（本地自主，不等主控）
- [ ] R3 晃动/倾斜 → 蜂鸣 + 灯红闪
- [ ] 每条规则单独测一遍，再合起来测

**本周交付：** 三条规则各一段视频（或一次现场演示）

### W4 · 断网可用
- [ ] 云端服务关掉，本地联动完全不受影响
- [ ] 事件写入本地缓存（环形缓冲）
- [ ] 服务恢复后自动补传
- [ ] 拔掉某块子板，其余不受影响

**本周交付：** 一段「关掉再打开」的完整演示视频

### W5 · 交互与数据
- [ ] 手机碰 NFC 标签 → 板子读出 → 生成巡检记录
- [ ] 实测：触发到执行的时延（20 次取平均）
- [ ] 实测：广播丢包率
- [ ] 整理成一张数据表（报告直接用）

**本周交付：** NFC 演示 + 数据表

### W6 · 收口
- [ ] 三分钟答辩脚本，掐表演练 3 遍
- [ ] 报告主体补齐（见第 5 节）
- [ ] 准备备用方案：某块板临场坏了怎么办
- [ ] 所有代码合并到主分支，能一键编译

**本周交付：** 可交付的报告 + 能演完的现场

## 3. 每周结束时，你自己拍板三件事

不要问别人，问自己：

1. **这周的系统比上周多了什么能力？** 说不出来 = 这周白干。
2. **如果明天答辩，我能演几分钟？** 演不到 1 分钟 = 进度落后。
3. **现在最没底的是哪一块？** 那就是下周的第一件事。

---

## 4. 卡住时的五级自查（先别问 AI）

按顺序走，80% 的问题到第 3 步就解决了：

1. **能复现吗？** 重启一次还在不在？偶发问题先记下来，别急着改。
2. **串口有打印吗？** 没有打印 = 程序没跑起来，先查烧录和 BUILD.gn。
3. **是环境问题吗？** 串口被占用 / 映射断开 / 波特率不对 / 文件没编进去——这四个占了新手问题的一大半。
4. **官方例程还能跑吗？** 能跑 = 你改的代码有问题；不能跑 = 环境或硬件有问题。
5. **还不行，再来问。** 问的时候带三行：**现象是什么、我试过什么、我猜是什么原因。**

> 这三行不是为了让我好回答，是为了让你自己想清楚。**能写出这三行的人，通常已经知道答案了。**

## 5. 组员任务与验收（防划水版）

派活的原则：**一件事 + 一个截止时间 + 一个能截图的交付物。**

| 角色 | 本周任务 | 交付物 | 验收标准 |
|---|---|---|---|
| 队友 A（有路灯板） | 跑通 SC1 调光 demo | 串口截图 | 能说清“改哪一行会让灯变暗” |
| 队友 B（有人体板） | 跑通 IS1 人体感应 | 串口截图 | 手晃过去，数值会变 |
| 队友 C（有物流板） | 跑通 ST1 晃动检测 + 蜂鸣 | 串口截图 | 晃动时能响 |
| 队友 D（无板也可） | 整理四板引脚与角色对照表 | 一张表 | 四块板 × 接口 × 用途，能对上原理图 |

**每人交作业时必须在群里发三行：** ①跑通了什么 ②遇到什么坑 ③截图。
只发截图不发坑的，说明没真跑。

## 6. 报告与开发并行表

| 周 | 开发 | 同时写报告的哪一章 |

| W5 | NFC + 数据 | 测试用例 + 实测数据 |
