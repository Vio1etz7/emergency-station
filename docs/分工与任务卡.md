# 四人分工与任务卡

日期：2026-11-12　项目：基于四块 BearPi-HM Nano 的校园应急物资站联动系统


---

## 一、分工原则

1. **一人一块板，一人一个节点。** 谁的板子谁负责，代码自己写、自己烧、自己测。
2. **主控放在农业板。** 主控是软件角色，放在 IA1（常供电、带执行器），路灯板降级成最简执行节点。
3. **接口由我定，实现各自写。** 消息格式统一（见第二节），所以四个人能真正同时开工。
4. **验收标准必须是"能看见的现象"**，不是"完成某模块开发"。

---

## 二、接口约定（开工前必须先认可这一节）

所有板子之间只发**一行 ASCII 文本**，用 `|` 和 `,` 分隔，不用二进制、不用 JSON。

```
节点 → 主控（上报）     NODE=<名字>,<字段>=<值>,...
主控 → 节点（命令）     CMD=<动作>,<参数>=<值>
```

具体例子：

| 方向 | 报文 | 含义 |
|---|---|---|
| IS1 → 主控 | `NODE=IR,P=1` | 检测到有人 |
| IS1 → 主控 | `NODE=IR,P=0` | 人走了 |
| ST1 → 主控 | `NODE=BOX,GPS=1,FIX=1,LAT_E6=31123456,LON_E6=121654321,BUZ=0` | 物资箱当前位置（FIX=1 表示已定位） |
| SC1 → 主控 | `NODE=LAMP,L=156,LED=0` | 当前光照 156，灯是关的 |
| 主控 → SC1 | `CMD=LIGHT,LED=1` | 开灯 |
| 主控 → ST1 | `CMD=BUZZ,ON=1` | 蜂鸣器响 |

端口分配（**每块板必须不同**，否则命令发串）：

| 板子 | 监听端口 |
|---|---|
| IA1 主控/网关 | 8889 |
| SC1 路灯 | 8890 |
| IS1 红外 | 8891 |
| ST1 物流 | 8892 |

主控收数据的端口统一 **8888**。

### 网络参数约定（换热点时必须全组同步）

| 项 | 约定 | 为什么 |
|---|---|---|
| 热点频段 | **必须 2.4 GHz** | Hi3861 不支持 5 GHz，连 5G 热点会一直重连失败 |
| SSID / 密码 | 群里统一通知，**不要写进本仓库** | 仓库是公开的，密码会被别人看到 |
| 网段 | 四块板 + 电脑必须在同一网段 | 安卓热点一般是 `192.168.43.x`，iPhone 是 `172.20.10.x` |
| 节点上报目标 | `主控板当前 IP : 8888` | 主控 IP 由热点 DHCP 分配，**换了热点就会变** |

**换一次热点 = 所有人重新改宏、重新烧录一次。**

主控板的 IP 在它自己的串口日志里（`DHCP state:OK` 后面几行），每次联调前先看一眼。

## 三、四张任务卡

### 任务卡 A —— 主控 / 网关（IA1）

| 项 | 内容 |
|---|---|
| 板子 | BearPi-HM Nano + E53_IA1 |
| 任务 | 在现有 5 任务程序上加两块：① 收所有节点的上报 ② 按规则向节点下发命令 |
| 输入 | 各节点的 `NODE=...` 报文 |
| 输出 | 串口状态行；对节点的 `CMD=...` 报文 |
| 验收标准 | 串口能同时打印出至少 2 个节点的数据；主控发一条命令，对应节点真的动作 |
| 截止 | 11-19 |
| 依赖 | B/C/D 至少有一块板能发报文过来 |

### 任务卡 B —— 事件节点（IS1 人体红外）

| 项 | 内容 |
|---|---|
| 板子 | BearPi-HM Nano + E53_IS1 |
| 任务 | 检测有人/无人，**带 20ms 消抖**，状态变化时上报一次 |
| 输入 | GPIO 电平（红外模块输出） |
| 输出 | `NODE=IR,P=1` / `NODE=IR,P=0`，状态不变时不重复发 |
| 验收标准 | 手在传感器前挥一下，主控串口出现 `P=1`；手移开 2 秒后出现 `P=0` |
| 截止 |11-19（接入主控） |
| 提示 | 参考 `C5_e53_is1_infrared` 例程 + `E2_lamp_node` 的网络部分 |

### 任务卡 C —— 物流节点（ST1 智慧物流）

| 项 | 内容 |
|---|---|
| 板子 | BearPi-HM Nano + E53_ST1 |
| 任务 | 物资箱出库后的**定位监控**：解析 GPS，算出相对基准点的位移，超过阈值就蜂鸣；把位置每秒报给主控；NFC 标签写巡检地址 |
| 输入 | GPS（UART1，9600）、NFC 标签（I2C1，NT3H） |
| 输出 | `NODE=BOX,GPS=1,FIX=1,LAT_E6=31123456,LON_E6=121654321,BUZ=0`（发到主控 8888）；本地蜂鸣 |
| 验收标准 | ① 串口出现 `FIX=1` 和经纬度 ② 主控打印"物资基准点已记录" ③ 把板子带走超过 20 米，主控打印"物资偏离 xx 米"并下发蜂鸣 ④ 手机碰 NFC，浏览器弹出巡检页 |
| 截止 | 已完成（commit `3332272`） |
| 说明 | **E53_ST1 没有加速度计**，原任务卡写的"检测倾斜/震动"实现不了，改为定位监控。这块实际工作量比原计划更重：NMEA 解析 + 距离计算 + NFC 写卡 + 本地 HTTP 巡检服务 |


### 任务卡 D —— 执行节点（SC1 智慧路灯）

| 项 | 内容 |
|---|---|
| 板子 | BearPi-HM Nano + E53_SC1 |
| 任务 | 从零写一个路灯节点：① 读光照 ② 连 Wi-Fi ③ 每秒向主控上报 ④ 收命令开关灯 |
| 输入 | 主控下发的 `CMD=LIGHT,LED=1` / `CMD=LIGHT,LED=0` |
| 输出 | 发给主控 8888 端口：`NODE=LAMP,L=<光照值>,LED=<0/1>`；自己监听 8890 |
| 验收标准 | ① 串口出现 `[CMD] listening on udp 8890` ② 电脑发 `CMD=LIGHT,LED=1`，灯真的亮；发 `LED=0` 灯灭 ③ 主控串口每秒都能看到 `NODE=LAMP,...` |
| 截止 | 11-19（与 B、C 同步接入主控） |
| 提示 | 传感器部分看 `C3_e53_sc1_pls` 例程（`E53_SC1_Init` / `E53_SC1_Read_Data` / `Light_StatusSet`）；网络部分参考 `E1_yizhan_node` 里的 `NetTask` 和 `CmdTask`——三块板的网络骨架是同一套，改字段就行 |
