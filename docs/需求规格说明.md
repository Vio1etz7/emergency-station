## 1. 项目背景与范围

### 1.1 要解决的问题

教学楼与宿舍的应急物资柜（急救包、灭火器、应急灯、对讲机）存在四个盲区：

| 盲区 | 后果 |
|---|---|
| 夜间无人值守，柜内照明常亮 | 费电，灯具寿命短 |
| 柜内应急灯、对讲机电池长期静置 | 电池鼓包、受潮锈蚀，故障平时看不出来 |
| 物资出库运输途中无人跟踪 | 调拨丢失、错送无人知晓 |
| 巡检靠纸质签到 | 无法证明"什么时候、谁、检查了哪个柜" |

### 1.2 系统目标

用四块开发板构成一个**断网可用**的局域联动系统：本地负责"感知—判断—动作"的实时闭环，云端只做统计与远程查看。

### 1.3 范围外（本期明确不做）

| 不做的事 | 理由 |
|---|---|
| 柜内恒温恒湿 | 物资均密封包装，调节温湿度无收益（指导教师已质疑过，见 CR-02） |
| 云端视频/图像 | 带宽与算力都不够 |
| 物资库存数据库 | 超出课程范围，NFC 只做到"巡检打卡" |
| 多柜级联（>4 节点） | `MAX_NODES 4`，本期固定四板 |
| 手机 App | 用浏览器打开巡检页代替 |

## 4. 功能需求

优先级：**必须**（不做则系统不成立）/ **应该**（显著提升价值）/ **可以**（有余力）/ **不做**（见 1.3）。

### 4.1 感知与上报

| 编号 | 需求 | 优先级 | 承载板 | 验收现象 |
|---|---|---|---|---|
| FR-01 | 主控（IA1）每 1 秒采集一次柜内温度、湿度、光照 | 必须 | #1 IA1 | 串口每秒打印一行 `T=.. H=.. L=..` |
| FR-02 | 红外节点（IS1）检测到"有人/无人"状态**变化**时上报一次，带 20 ms 消抖 | 必须 | #3 IS1 | 挥手串口出现 `NODE=IR,P=1`，手离开 2 秒后 `P=0` |
| FR-03 | 路灯节点（SC1）每 1 秒上报光照值与当前灯状态 | 必须 | #2 SC1 | 主控见 `NODE=LAMP,L=..,LED=..` |
| FR-04 | 物流节点（ST1）每 1 秒上报 GPS 定位（`FIX`/`LAT_E6`/`LON_E6`） | 必须 | #4 ST1 | 主控见 `NODE=BOX,GPS=1,FIX=1,LAT_E6=..` |
| FR-05 | 所有上报统一发往主控 **8888** 端口，格式为一行 ASCII：`NODE=<名>,<键>=<值>,...` | 必须 | 全部 | 抓包/串口可见；主控能解析 |
| FR-06 | 主控自动学习节点 IP（从报文源地址），不需要手工配节点地址 | 应该 | #1 | 节点重启换 IP 后仍能收到命令 |
| FR-07 | 各节点监听各自命令端口：主控 8889、路灯 8890、红外 8891、物流 8892 | 必须 | 全部 | 串口打印 `[CMD] listening on udp 8890` 等 |

### 4.2 联动规则（本项目的核心）

| 编号 | 规则 | 触发条件 | 动作 | 优先级 |
|---|---|---|---|---|
| FR-08 | R1 人来灯亮 | 红外 `P=1` 且主控光照 `< 20 lux` | 向路灯发 `CMD=LIGHT,LED=1`；柜内补光灯亮 | 必须 |
| FR-09 | R2 人走延时灭灯 | 红外由 1 → 0 | 保持 30 秒后发 `CMD=LIGHT,LED=0`；若期间又检测到人则重新计时 | 必须 |
| FR-10 | R3 环境异常 | 温度 `> 32 ℃` 或湿度 `> 75 %`（持续判定） | 本地风扇开启 + 向物流节点发 `CMD=BUZZ,ON=1` 远程提示 | 必须 |
| FR-11 | R4 物资偏离 | 物流节点位置与**基准点**距离 `> 20 m` | 主控置告警、蜂鸣（`CMD=BUZZ,ON=1`）、路灯点亮 | 必须 |
| FR-12 | R5 告警自动解除 | 触发条件消失（回到基准点附近 / 定位恢复） | 告警解除、发 `CMD=BUZZ,ON=0`、串口打印"告警解除" | 必须 |
| FR-13 | R6 定位丢失 | 已有基准点但连续 30 秒收不到有效定位 | 判定为异常并告警 | 应该 |
| FR-14 | 告警保持 10 秒后自动复位，避免每条报文都重复触发 | — | `ALARM_HOLD 1000 tick = 10 s` | 应该 |

### 4.3 人工干预

| 编号 | 需求 | 优先级 | 验收现象 |
|---|---|---|---|
| FR-15 | 电脑/手机可向主控 8889 发送 `LED=1`/`LED=0`/`FAN=1`/`FAN=0` 直接控制执行器 | 必须 | 串口出现 `[CMD] 192.168.x.x => LED=1`，灯立刻亮 |
| FR-16 | 手动干预后进入 30 秒手动模式，期间自动规则不覆盖人工操作 | 必须 | 串口打印 `[CMD] manual mode for 30 s`；该时段内挥手不会灭灯 |
| FR-17 | 支持 `BASE` 命令清空物资基准点（重新锚定） | 应该 | 串口打印基准点已清除 |

### 4.4 状态与可靠性

| 编号 | 需求 | 优先级 | 验收现象 |
|---|---|---|---|
| FR-18 | 主控每 2 秒打印一行系统总览：环境值、执行器状态、在线节点数、告警状态、最近事件 | 必须 | 串口 `[GW] T=.. 节点在线=3/3 BOX=正常(0m)` |
| FR-19 | 节点超过 15 秒无消息判定为掉线，并从在线计数中剔除 | 必须 | 拔电某块板，15 秒后在线数减 1 |
| FR-20 | 向掉线节点发命令时丢弃并提示，不得阻塞其他规则 | 必须 | 串口打印 `[GW] 节点 LAMP 不在线，命令丢弃` |
| FR-21 | 无线断开后自动重连，不重启系统 | 应该 | 热点重启后板子自行恢复上报 |

### 4.5 巡检（NFC）

| 编号 | 需求 | 优先级 | 验收现象 |
|---|---|---|---|
| FR-22 | 物流节点开机把巡检 URL 写入 NT3H 标签（NDEF URI 格式） | 应该 | 手机贴一下弹出浏览器并打开巡检页 |
| FR-23 | 巡检页记录设备号与时间（本地 HTTP 服务 + sqlite3） | 应该 | 浏览器显示"巡检成功"，服务端新增一条记录 |

## 5. 非功能需求

| 编号 | 需求 | 指标 | 现状 |
|---|---|---|---|
| NFR-01 | **断网可用**：无外网、无云平台时，四板联动必须完整可用 | 拔掉路由器后本地规则 100% 可用 | 已满足（纯 UDP 局域网） |
| NFR-02 | 实时性：从传感器变化到执行器动作 | ≤ 1 秒（含采集周期与转发） | 采集 1 s + 判定即发，实测 ≤ 1 s |
| NFR-03 | 并发规模：单网关可管理节点数 | 4（`MAX_NODES 4`） | 固定四板，不扩容 |
| NFR-04 | 资源约束：RAM 352 KB / Flash 2 MB | 七任务栈合计 47104 B ≈ 46 KB | 满足，剩余约 300 KB |
| NFR-05 | 网络范围：四板与电脑必须处于同一 2.4 GHz 局域网 | 同一网段、可互 ping | 手机热点或路由器；5 GHz 连不上 |
| NFR-06 | 配置集中：Wi-Fi 与网关 IP 只在宏定义处修改 | 每节点 ≤ 3 个宏 | 已满足（`WIFI_SSID`/`WIFI_PASSWORD`/`GATEWAY_IP`） |
| NFR-07 | 可移植：节点间只依赖 ASCII 报文，不依赖具体芯片 | 换板子只改驱动层 | 已满足（四个节点程序结构一致） |
| NFR-08 | 可演示：不依赖教室网络与云服务 | 一部手机热点即可 | 已满足 |
| NFR-09 | 可维护：单节点代码 ≤ 800 行、单函数 ≤ 60 行 | — | E1 约 700 行，E4 795 行 |
| NFR-10 | 成本：不新增器件 | 0 元 | 全部使用已有套件 |

## 7. 需求变更记录

### CR-01：物流节点由"倾斜检测"改为"GPS 定位监控"（2026-11-20）

| 项 | 内容 |
|---|---|
| 提出人 | C（ST1 负责人） |
| 变更原因 | E53_ST1 扩展板**只有 GPS + 蜂鸣器，没有加速度计**，无法检测倾斜/震动。原需求（任务卡 C v1.0）基于错误硬件假设 |
| 影响分析 | 原"柜内静置监测"叙事不成立（柜子不会移动）；改为"**出库运输监控**"：物资出库后跟踪位置，偏离基准点 20 米告警 |
| 对代码的影响 | 网关 BOX 分支重写（解析 `FIX`/`LAT_E6`/`LON_E6`，新增距离计算与基准点逻辑）；`BOX_MOVE_THRESHOLD_METERS` 5 → 20 米（民用 GPS 静止漂移 3~10 米） |
| 对文档的影响 | 任务卡 C 报文格式与验收标准、README 角色说明、本文件 FR-04/FR-11 |
| 结论 | 批准。工作量由"读一个加速度计"变为"GPS 解析 + 距离计算 + 基准点管理"，**实际更重**，不是减负 |

### CR-02：柜内环境监测由"恒温恒湿"改为"异常监测 + 通风"（2026-10-29）

| 项 | 内容 |
|---|---|
| 提出人 | 指导教师 |
| 变更原因 | 绷带、酒精等物资均密封包装，调节柜内温湿度没有实际收益 |
| 结论 | 监测对象改为柜内应急灯、对讲机、电池（锂电池高温鼓包、受潮锈蚀），执行器只做"报警 + 通风"，不做闭环调节 |
